## Failures

1. **The model doesn't use the `[P#]` format.** Raw replies: `P1: … [S1][S2].`, `P2: [P2] MISSING.`, `P1: [S1] MISSING`. The prompt lists the parts as `P1: …`, and the model copies that. The parser only knows `[P1]`, so:
   - **Part tracking breaks.** q14 really missed P2, but tracking put P1 and P3 as missing, so targeted retrieval searched for the wrong parts.
   - **"P1:" / "P2:  MISSING." reach the person.**
2. **A sentence with no content passed the check.** q19's `P1: [S1] MISSING` was split at the `[S1]` tag into `P1: [S1]`. That has a citation and no numbers, so it passed and was shown. The trailing `MISSING` was then ignored. **This is a real regression from run 1.**
3. **The per-minute token limit blocked the targeted round.** Groq reported tokens left 7,461 → 6,138 → 5,989 → 3,912 during q05 and q14. The q14 targeted draft (8 passages plus 700 max tokens) didn't fit. Groq's reset was 30.7 s, more than the time left before the deadline, so the governor failed fast, as designed, and the answer was marked cut short. **With 8K tokens per minute, a 3-call answer uses about half a minute's budget.**
4. The offline oracle always wrote the exact format, so the offline benchmark couldn't catch failures 1–2.
